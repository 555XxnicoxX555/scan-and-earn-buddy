# UX Report Checklist

Use this checklist before delivering a report.

## Evidence

- The report names the original objective.
- The report lists the actual areas reviewed.
- Claims are backed by files, screenshots, commands, or clear observations.
- Verification commands are included only if they were run.
- Sensitive data is omitted or redacted.

## Visual Content

- Include real screenshots when possible.
- Include representative before/after examples only when real before screenshots are missing.
- Label representative examples clearly.
- Use cards, badges, tables, timelines, and code blocks for scanability.

## Decisions

- Explain why each major UX decision improves the user experience.
- Separate shipped changes from pending recommendations.
- Include tradeoffs and limitations.

## Delivery

- Report folder is outside the main repo if requested.
- `index.html` loads locally.
- Images are not broken.
- Final response includes path, open instructions, summary, and validation.
